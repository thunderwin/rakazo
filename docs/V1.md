# V1 产品决策与范围

> 状态：已确认方向，尚未实现。确认日期 2026-10-20。

## 1. 决策

V1 采用 **单设备 local-first**：

- Agent 循环、工具执行、bot 配置、对话、记忆和本地数据库都在用户客户端。
- 服务器只保留账号、充值/额度、模型网关、设备管理和监控。
- 模型网关是主要收入路径。客户端不直接持有模型供应商的长期密钥。
- V1 不做多设备同步、团队协作、团队电脑、移动端和本地模型。

一句话：

> 服务器卖 AI 调用和账号服务；客户端拥有用户的数据和 Agent 执行环境。

## 2. 目标流程

```text
用户下载并安装客户端
  -> 登录或注册（服务器鉴权）
  -> 客户端生成设备身份并保存到系统钥匙串
  -> 客户端创建本地 SQLite 数据库
  -> 从内置模板创建默认 bot
  -> 用户发消息
  -> 本地 Agent runtime 调用服务器模型网关
  -> 模型返回工具调用
  -> 本地 runtime 执行 shell / 文件 / 浏览器操作
  -> 结果写入本地数据库
  -> UI 显示过程和结果
```

## 3. 服务器职责

服务器保持薄，但必须保留以下能力：

- 注册、登录、会话和账号安全
- 订阅、充值、额度、用量记录
- 模型网关：鉴权、限额、转发、流式返回
- 设备注册、设备撤销、短期访问 token
- 崩溃上报、基础监控和审计元数据
- 客户端版本检查和更新 feed

服务器**不保存**：

- bot 配置和 instructions
- 对话和消息正文
- 用户记忆
- 本地文件和浏览器内容
- Agent 的工具执行日志正文

模型网关会看到请求中的 prompt 和模型返回内容。这是计费和风控的必要条件，必须在
隐私政策中明确说明。V1 不承诺“服务器完全看不到内容”。

## 4. 客户端职责

客户端包含：

- Electron 壳和本地 Web UI
- 本地 Agent runtime（Pi 循环）
- 本地 SQLite 数据库
- shell、文件、应用启动等本地工具
- 浏览器扩展桥接，用于用户现有浏览器和登录态
- 本地定时任务
- 本地日志、备份和导出

客户端不包含：

- 模型供应商的长期 API Key
- 管理员 token
- 其他用户的凭据
- 服务器数据库连接信息

## 5. 模型网关

协议见 `docs/MODEL_GATEWAY.md`。

### 5.1 调用方式

```text
本地 Agent runtime
  -> POST /v1/model/...（短期设备 token）
  -> 服务器鉴权、扣额度、选择 provider
  -> 转发到模型供应商
  -> SSE 流式返回客户端
```

### 5.2 要求

- 短期 token，与设备绑定，可撤销。
- 按用户、设备、模型和 token 用量限额。
- 失败重试和超时由网关统一处理。
- 记录用量元数据，不把对话正文写入业务数据库。
- 对异常频率、共享账号和滥用做风控。
- 模型供应商密钥只存在服务器密钥库。

### 5.3 不允许

- 把 OpenAI/Anthropic 等长期 key 打进客户端。
- 让客户端直接调用供应商并绕过额度。
- 在客户端做“扣费”或“额度判断”作为唯一依据。

## 6. 本地数据

使用 `better-sqlite3`（SQLite，WAL 模式，本地 runtime 作为唯一写入口），至少包含：

- bots
- threads
- messages
- bot memory / memory documents
- routines
- tool run records
- settings
- schema migrations

要求：

- 数据库位于应用数据目录，权限仅当前用户可读。
- 敏感字段加密；备份文件也需要加密。
- 提供导出和恢复；V1 不做云端同步。
- 升级时执行本地迁移；失败要能回滚或保留备份。
- 本地数据库是唯一事实来源；服务器不保存对话副本。

## 7. 浏览器和本地工具

- 用户现有浏览器的登录态通过浏览器扩展访问，不复制 Cookie 文件。
- 本地 Agent 通过 Native Messaging 或本地 WebSocket 与扩展通信。
- 扩展需要按站点授权，并提供暂停和撤销入口。
- shell、文件和屏幕工具必须有明确授权、可见状态和停止按钮。
- 网页内容、工具输出和其他 bot 的内容都按不可信数据处理。

## 8. 更新策略

V1 只做最小闭环，详见 `docs/UPDATES.md`：

- prompt、bot 模板、模型目录和功能开关：签名配置包，下载后立即生效，不重启。
- Web UI：版本化资源，下次页面加载或轻量 reload 使用新版本。
- 本地 runtime：后台下载、校验，下次启动生效；V1 不做进程热切换。
- Electron/Chromium/原生模块：后台下载，退出时安装，必须重启。
- 本地数据库迁移：在副本上执行，成功后原子替换，失败保留旧库。

V1 不承诺 Electron 本体无重启更新。

## 9. V1 最小验收

- 用户能安装客户端、注册/登录。
- 登录后自动创建设备身份和本地数据库。
- 能从内置模板创建一个 bot 并发消息。
- 消息通过服务器模型网关返回。
- Agent 能调用至少一个本地工具（建议 shell 和文件）。
- 浏览器扩展能读取并操作用户当前标签页。
- 对话和 bot 配置在重启后仍在。
- 服务器只记录账号、额度、设备、用量和错误元数据。
- 卸载/重装后，用户可以通过导出文件恢复本地数据。
- prompt/模板更新后不重启 App 即可生效。
- runtime 更新下载失败或签名错误时不影响当前使用。
- Electron 更新在退出时安装，不打断当前任务。

## 10. V1 非目标

- 多设备同步
- 团队 Space、团队电脑、多人协作
- 移动端
- 本地模型权重
- 模型市场、插件市场
- 服务器端 Agent 执行
- 服务器端对话历史
- 复杂的自动更新灰度系统
- runtime 热切换和完整的 Launcher 版本目录

## 11. 实施顺序

1. 服务器：账号、额度、模型网关、设备 token、基础监控。
2. 客户端：本地 SQLite schema 和 repository。
3. 客户端：本地 Agent runtime 和本地工具。
4. 客户端：本地 API/IPC，把现有 Web UI 接到本地后端。
5. 浏览器扩展和 Native Messaging。
6. 本地备份、导出、恢复。
7. 打包、签名、配置包更新和小范围测试。

前四步完成之前，不要开始做多设备或团队能力。
