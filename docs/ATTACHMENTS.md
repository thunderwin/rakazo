# 本地附件

> 状态：个人终端版本已实现。核实日期：2026-10-21。

## 1. 范围

用户可以在直接聊天和群聊中附加文件：

- 每条消息最多 4 个文件。
- 单文件默认上限 10 MiB。
- 类型沿用原版共享附件白名单。
- 文件正文保存在当前账号的本地 SQLite `artifacts` 表。
- 服务器不接收或保存附件副本。

支持的图片为 JPEG、PNG、WebP 和 GIF；其他允许类型包括 PDF、纯文本、Markdown、CSV、HTML、
JSON、ZIP、MP4 和常见音频格式。

## 2. 消息与模型

消息 block 复用原版结构：

- 图片：`kind: "image"`。
- 其他文件：`kind: "file"`，包含名称、MIME、大小。

每一轮最多把本轮图片作为 `currentTurnImages` 交给 Pi/模型，历史消息只保留
`[image: name]` 或 `[file: name (...)]` 文本占位符。

非图片文件当前只把名称、MIME 和大小作为本轮上下文提示给 Agent；不会自动抽取 PDF、ZIP、
Office 或媒体正文。需要读取本地文件时，Agent 可以使用已有的 workspace 文件工具。

## 3. 交互

本地 composer 支持：

- Attach files 文件选择。
- 拖放文件。
- 从剪贴板粘贴文件。
- 图片缩略图和非图片文件 chip。
- 发送前移除附件。
- 仅附件发送，不要求 caption。

消息中的图片会读取本地 artifact 并显示；所有附件都可以下载。图片读取失败时显示明确的
本地加载错误，不静默隐藏。

## 4. 边界

- 附件作用域必须匹配目标 bot 或 group；跨目标 ID 会被拒绝。
- 文件选择器和服务端 IPC 都校验类型、数量、大小。
- 模型网关会看到本轮图片或文件元数据提示。
- 详细文件正文不会上传控制面，也不会写入 Activity 日志。
- 群聊附件属于该 group，不会自动复制到成员 bot 的私有附件。
